# Web 3D 出力ディレクトリ

v003 では、主モデル、モバイル用モデル、出力マニフェスト、ローカルプレビューを実装済み。`index.html` を直接開くか、ナビゲーションの「ロボット全体設計」から開く。モデルと操作用スクリプトは同梱され、インターネット接続や Blender の起動は不要。HTTP プレビューには、プロジェクト直下の `プレビューを起動.command` または `serve.py` を使う。Node.js は開発時の検証用であり、閲覧には不要。以下の規則は引き続き適用する。

予定する成果物：

```text
web/
├── robot_web.glb
├── robot_web_lod1.glb
├── export-manifest.json
└── textures/
```

Web ページで表示名から部品を推測しない。GLB node 名の `part__<component_id>` は `../data/components.json` の `id` と完全に一致させる。

Web 側では次の内容を独立したデータとして扱い、モデルに焼き込まないことを推奨する。

- 多言語の表示テキスト。
- 仕様、設計理由、根拠リンク。
- 分解表示のオフセット。
- センサ FOV/可動範囲の表示切り替え。
- Dashboard のリアルタイム状態と部品 ID の対応。

文章や運用データを変更しても GLB を再出力する必要がなくなる。

## ローカル表示用ファイルの更新

`app.bundle.js` は Three.js と操作ロジックを含む通常の JavaScript。`portable/` には部品データ、参考資料の表示用テキスト、GLB と同じバイト列を Base64 化したモデルを保存する。ファイルとして直接開く場合のみ同梱データを使い、HTTP では元の JSON / GLB を相対 URL で読む。画像、PDF、元資料へのリンクは元の相対パスを維持する。

`app.js`、モデル、部品データ、参考資料の本文を更新した場合は、このディレクトリで `npm ci`、`npm run build` を実行する。通常の閲覧には Node.js や Python は不要。フォルダーは一式で移動し、OneDrive のファイルは端末に保存してから開く。
