# 当前机器人 3D 资产构建 Guideline

## 1. 最终目标

最终交付不是单一的 Blender 场景，而是一套可追踪的数字资产：

- `robot_master.blend`：保留原始层级、单位、材质、关节原点和装配位置；
- `robot_web.glb`：面向网页的轻量模型；
- `components.json`：零件 ID、型号、规格、说明、证据和设计理由；
- 普通装配视图、爆炸视图和重点系统局部视图；
- 可选择性显示的相机视锥、LiDAR FOV、Lift 行程、轮组转向轴和 Arm 工作空间辅助图形。

本次提供的参考图定义了第一版视觉方向：浅灰背景、等轴测视角、整机装配图与爆炸图成对呈现，主体保持真实材料色，用较大的系统级间距让底盘、轮组、门架、Lift、传感器和执行机构一眼可分。它是展示风格参考，不是当前机器人几何来源。

网页端点击一个部件时，应能区分三类信息：

1. **它是什么**：品牌、型号、数量、接口、规格；
2. **它如何安装**：尺寸、坐标、连接件、父子装配关系；
3. **为什么这样设计**：目标、约束、比较方案、验证结果和未解决问题。

## 2. 事实、估算和设计说明分层

每个数值或结论必须带一种状态：

| 状态 | 含义 | 可否用于最终精确模型 |
|---|---|---|
| `measured` | 在实机上用尺、卡尺、角度计或标定流程得到 | 可以，需保存日期和方法 |
| `manufacturer` | 厂家图纸或数据表给出 | 可以，但安装位置仍需实测 |
| `runtime` | 当前 ROS/控制配置实际使用 | 可用于运行态展示，不自动证明机械尺寸 |
| `model-derived` | 从原始 CAD/STL/DAE 得到 | 可以，但需核对是否与安装版本一致 |
| `photo-estimated` | 仅由照片比例估计 | 只用于块模型 |
| `historical` | 旧安装或已停用参数 | 仅供解释演变，不进入当前装配 |
| `conflict` | 两个现有来源互相矛盾 | 不得选择其一伪装成事实 |
| `unknown` | 尚无证据 | 使用明显的占位几何 |

设计说明也必须区分“当时真实决策依据”和“事后合理解释”。例如 Pan/Tilt 角度只有在已有测试、FOV 计算或设计记录支持时，才能写成“为了让 local planner 看清前方某段范围而选择”；否则应写成“当前假设，待用相机视锥和 local costmap 覆盖实验验证”。

## 3. 坐标、单位与基准

- ROS/GLB 使用米，Blender 场景单位设为 Metric、Unit Scale `1.0`。
- 机械测量表建议记录毫米，导入 Blender 时统一转换为米。
- 整机基准沿用 ROS：`X` 前、`Y` 左、`Z` 上。
- `base_link` 当前位于轮轴高度，离地约 `0.1125 m`；地面投影使用 `base_footprint`。
- 每个运动件的对象原点必须放在真实旋转轴或平移轴上，而不是网格几何中心。
- D435、MID360、SO101 的 optical/link frame 与视觉网格原点可能不同，二者必须分别保留。

不把 `robot.urdf.xacro` 当作唯一尺寸真值。2026-09-20 实测已经确认底部
frame 水平包络为 X=`700 mm`、Y=`600 mm`，结构上平面高度为
`300/515/620/1330 mm`；主结构使用 4040，前方 Arm/Camera/LiDAR 垂直支架
使用 2020。URDF 的 `670 × 600 × 580 mm` 单 box 只保留为旧的运行简化模型，
不得用于 Blender 真实结构。

Lift 机械行程也已最终确认为 `200 mm`，旧 `230 mm` Arm 可视化 span 已停用。
仍保留的主要冲突只有 MID360 安装 transform：注释为
`x=-0.240 m、z=0.6875 m`，运行 property 为 `x=+0.240 m、z=1.38 m`。
`1330 mm` 是结构上平面高度，不足以替代 MID360 安装底面原点测量。

## 4. 建模精度分级

### L0：结构块模型

- 正确的整体外廓、轴心、主要部件位置和运动关系；
- 缺失部件用简单 box/cylinder，并使用醒目的 `PLACEHOLDER` 材质；
- 用于检查比例、爆炸方向、镜头构图和网页交互层级。

### L1：装配识别模型

- 设备外形、主要接口、安装支架和紧固件位置可识别；
- 可以清楚区分轮组、电机、驱动器、相机、LiDAR、Lift、Arm、计算机、电源和控制板；
- 足以承担网页硬件说明和爆炸图。

### L2：设计细节模型

- 自制件孔位、折弯、3D 打印结构、线束固定点和安装公差可信；
- 用于解释设计理由、维护拆装和重新制造；
- 不要求把每条螺纹或电路板元件都做成高面数几何。

第一轮先完成全机 L0，再把有现成 CAD 的 SO101/D435 提升到 L1；不要先把单个零件做得极细而整机基准仍不确定。

## 5. Blender 场景层级

推荐 Collection：

```text
ROBOT
├── 00_REFERENCE      照片、测量标尺、URDF 辅助对象；不导出
├── 10_BASE           底盘框架、面板、护罩
├── 20_MOBILITY       三套轮、转向、电机、减速机
├── 30_LIFT           滑台、滑块、立柱、支架、驱动器
├── 40_ARM            SO101、腕部相机与安装件
├── 50_PERCEPTION     MID360、D435、Pan/Tilt
├── 60_ELECTRICAL     NUC、电源、控制器、急停、通信转换器
├── 70_CABLES         主要线束与拖链
├── 80_HELPERS        FOV、行程、轴线、包络；按需导出
└── 90_EXPLODED       爆炸控制空对象与展示注释；不作为真实装配尺寸
```

对象命名使用 ASCII 稳定 ID，例如：

```text
part__perception.camera.d435
part__lift.stage.eas
part__mobility.drive.front_left
helper__perception.camera.d435.fov
anchor__lift.stage.eas.exploded
```

`components.json` 中的 `id` 必须与 `part__` 后的字符串一致。显示名称可以是中文、日语或英文，但 ID 不随文案改变。

## 6. 原点、层级与爆炸图

每个可交互部件至少保存：

- `assembly_transform`：真实装配位姿；
- `exploded_offset`：相对装配位姿的展示偏移；
- `parent_id`：机械装配父级；
- `explode_group`：爆炸时同步移动的组合；
- `pivot_type`：`fixed`、`revolute`、`continuous` 或 `prismatic`。

爆炸图遵守以下规则：

- 先拆大系统，再拆子组件；方向尽量沿真实安装/拆卸方向；
- 线束可隐藏或用简化曲线显示，避免爆炸后形成视觉噪声；
- 不把电气连接关系仅靠空间位置表达，网页另用 connection 数据说明；
- 正常装配与爆炸视图使用同一套对象，不维护两份独立模型；
- Web 动画从装配 transform 插值到 exploded transform，用户可暂停、反向或聚焦单个系统。

第一版建议同时保留两个预设镜头：`assembled_isometric` 与 `exploded_isometric`。二者保持相同方位和近似投影比例，便于用户直观看出每个零件从哪里拆出。

## 7. 运动和辅助可视化

建议把以下内容做成单独可开关层：

- Lift：机械 `0–200 mm` 行程、日常软件区间 `15–185 mm`、上下 keep-out；
- SO101：6 个关节轴、当前软限位和末端工作空间近似；
- D435：RGB/Depth 视锥、Pan/Tilt 轴、neutral 和已测 scan poses；
- MID360：水平/垂直 FOV 与安装倾角；
- 轮组：三轴 steering 旋转轴、轮接地点和运动学位置；
- 安全：急停按钮位置、Lift/Arm/底盘运动包络和可能夹点。

辅助对象默认不参与真实外观渲染；在网页中作为“设计解释”开关显示。

## 8. 设计理由记录

每个重点部件使用 [DESIGN-NOTE-TEMPLATE.md](DESIGN-NOTE-TEMPLATE.md) 独立记录。至少回答：

- 要解决的任务是什么；
- 选择前有哪些约束；
- 为什么选择这个型号、位置、高度或角度；
- 被比较或被放弃的方案是什么；
- 哪些数据证明设计有效；
- 哪些内容只是待验证假设；
- 这个决策与导航、感知、操作、安全或维护的关系。

建议优先补写：

1. D435 Pan/Tilt 的位置、轴角、neutral pose 与 local planner/costmap 观察范围；
2. MID360 的高度、倾角，以及定位与近场避障职责分工；
3. Lift 型号、200 mm 行程、安装高度、15 mm 端点保护和 Arm 可达范围；
4. 三轮全向底盘的轮位、BLV-R/XH540 选型与结构限制；
5. SO101 安装在 Lift 滑块上的方向、高度和腕部相机用途。

## 9. 照片和测量采集规范

- 整机保持同一姿态，Lift、Pan/Tilt 和 Arm 位置要记录数值；
- 使用前、后、左、右、顶、底六个尽量正交的视角；
- 相机尽量远、使用长焦，减少透视畸变；
- 每张局部图放置同一平面的尺或标定板；
- 对每个支架拍“安装状态”和“拆下后的正反面”；
- 文件名包含日期、部件 ID、视角和标尺，例如 `20260921_lift.stage.eas_left_ruler.jpg`；
- 尺寸记录必须说明测量端点，不只写一个无定义的长度；
- 线束拍摄应能追踪起点、终点、连接器和固定点。

## 10. Web 资产导出

- 主格式使用 GLB/glTF 2.0；原始 STL/DAE 不直接在网页加载。
- 保留可点击部件的独立 mesh/node；同型号紧固件可实例化。
- 视觉细节用法线贴图和材质表达，避免不必要的高面数。
- 为桌面网页准备主模型，为低性能设备准备简化 LOD。
- 导出前应用 scale，但不要破坏关节 pivot 和父子层级。
- 每次导出记录 Blender 文件版本、导出日期、GLB hash 和 `components.json` schema version。

建议网页交互：

- hover 高亮，click 固定选择；
- 装配/爆炸滑杆；
- 按系统筛选；
- 规格、安装、设计理由、证据四个信息页签；
- 辅助显示 FOV、运动范围和连接关系；
- `measured/manufacturer/estimated/conflict` 证据徽章；
- 从说明跳转到原始照片、手册或标定记录。

## 11. 阶段验收

### Phase A：证据与骨架

- P0 尺寸不存在未解释冲突；
- 整机 L0 外廓和轴心与实物照片一致；
- 所有主要系统有稳定 component ID。

### Phase B：装配与爆炸

- SO101、D435 复用网格完成；MID360、轮组、Lift、底盘达到 L1；
- 爆炸顺序和拆卸方向合理；
- 正常装配位姿不会因爆炸动画被修改。

### Phase C：网页与说明

- 每个热点能打开正确部件资料；
- 重点设计说明有证据状态；
- GLB 在目标网页流畅加载，移动端使用简化版本；
- 许可证和第三方归属信息可从网页访问。

## 12. 变更纪律

- `references/` 不手工改写；需要更新时重新复制并更新 `SOURCE-MANIFEST.md`。
- Blender 中新增零件前先在 `components.json` 分配 ID。
- 任何尺寸修改必须同时记录来源、日期和旧值处理方式。
- 当前实机与设计草案分开：草案使用 `proposal` 状态和独立 Collection。
- 不从美术模型反向宣称机械精度；Web 模型是说明资产，不代替生产 CAD。
