🦾 1. ARM 基本 3 モードの設計と検証

移動ロボットに ARM を追加するにあたり、安全な起動から遠隔操作、プログラム制御までを切り分けて扱えるよう、3 つの基本運転モードを設計した。いずれも実機で動作を確認済み。

モード関節の状態主な用途
Real to SimTorque OFF（自由に動かせる）起動時の安全な準備状態、状態確認、Real-to-Sim の状態同期
TeleoperationLeader / Follower 構成人手による遠隔操作、動作の示教、学習用データ収集
Code to Sim & RealTorque ON（プログラム制御）IK 制御、記録動作の再生、VLA Policy、Agent Skill の実行
MODE 1 Real to Sim Mode
  • 起動直後は全関節が Torque OFF で、出力トルクなしに自由に動かせる。
  • ARM 起動後の安全な準備状態として、また Real-to-Sim の状態同期に使用する。
Real to Sim Mode の動作手で動かした実機の姿勢がシミュレーション側へ反映される
MODE 2 Teleoperation Mode
  • Leader / Follower 構成。実際にタスクを実行するのは Follower ARM。
  • Leader ARM は人手による遠隔操作と動作示教に用いる。
  • 今後、模倣学習・VLA などの実操作データが必要になった際も、Leader ARM による示教でデータ収集ができる。
Teleoperation Mode の動作Leader ARM の操作に Follower ARM が追従
MODE 3 Code to Sim & Real Mode
  • ARM をプログラムから直接制御するモードで、各関節は Torque ON。
  • IK 制御、記録済み動作の再生、VLA Policy など、プログラム化された制御方式を実行できる。
  • 将来の実タスク実行と Agent Skill 呼び出しを主な対象とする。Touch Anything はこのモード上で動作する。
Code to Sim & Real Mode の動作プログラム指令で実機 ARM を駆動

🎯 3. 最終接近・Press 段階の課題と改善方針
解決済み 開発中に見つかった問題
  • 初期位置の推定誤差：追加の Calibration でカメラと ARM の位置関係を補正し、改善した。
  • 視覚的な「偽の整列」：Y/Z を同時に補正していたため、見かけ上は整列していても実際の Press 位置がずれることがあった。補正順を「Z → Y」に変更して解決した。
課題 現在残っている主な課題

Touch Anything の主体フローは一通り動作するようになったが、最終 Press 直前の位置合わせ精度が十分ではない。主な原因として、接近中の動作・補正が連続的ではなく、最終位置に誤差が残ることが考えられる。

原因 原因分析
  • 目標位置と ARM 動作の更新が不連続：従来は「SAM で再分割 → 軌道生成 → 実行 → 停止・整定待ち → 再観測」を 1 ステップずつ繰り返しており、実際の観測間隔は 6〜13 秒に達していた。停止のたびに荷重による沈み込みや振動が生じ、再始動時にも新たな誤差が乗る。
  • SO-ARM101 の精度の限界：低コストなアームであり、絶対位置精度・繰り返し位置精度が限られる（荷重下では Z 方向に系統的な下振れが出る）。
  • 単発の視覚結果への依存：ある一時点の視覚定位結果だけで最終 Press を実行すると、誤差が蓄積しやすい。
新方針 連続視覚フィードバック（Visual Servoing）

最終位置を単一の目標位置から決めるのをやめ、ARM が接近している間、視覚特徴量を実時間で計算し続け、連続的なフィードバックで運動方向を修正して最終 Press 位置へ収束させる方式に切り替える。ARM 自体の位置誤差と、単発の視覚推定誤差の両方の影響を小さくすることが狙い。

SAM 2最初に対象を確定（1 回のみ）
→
KLT 追跡連続追跡（約 25 Hz）
→
画像誤差制御10 Hz で Y/Z・+X を補正
→
10 ステップ動作ブロック毎周期で置き換えて連続実行
  • 追跡が外れたときのみ ORB 特徴で再同定し、それでも失敗した場合に SAM の再実行または人の再確認へ進む。
  • 実行側は 0.5 秒分（10 ステップ）の動作ブロックを持ち、新しい観測のたびに未実行の後半を置き換える。追跡・計算・実行が重なって動くため、停止・再始動による誤差が生じにくい。
  • 制御ループが止まった場合は独立したウォッチドッグが完了前に HOLD へ移行し、停止時は現在姿勢を保持する。

次のステップ 検証計画（Isaac-first）

実機での試行は時間と安全面のコストが高いため、まず Isaac Sim で同一のトピック・テレメトリ構成を再現し、そこで方式を固めてから実機で 1 回だけ検証する。

  1. Isaac Sim 上で Arm Camera・関節状態・TF・視覚サーボ用トピックを実機と同じスキーマで再現する。
  2. 画像遅延、IK 遅延、DDS の背圧、関節応答の遅れ、Z 方向のモデル誤差を注入し、動作ブロックの置き換え・追跡の締切遵守・停止直後の凍結を確認する。
  3. FAR → NEAR の全行程で追跡喪失・タイムアウト・Z 下振れが出ない状態になるまで、Z 補償・速度制限・ブロック長を調整する。
  4. 同じパラメータを実機に反映し、人が監督する FAR → NEAR を 1 回実施する（Press 実行前は確認待機で HOLD）。判定は Z 下振れ 12 mm 以内、ウォッチドッグ不作動、動作ブロックの再計画数が指令と共に増加していること。
