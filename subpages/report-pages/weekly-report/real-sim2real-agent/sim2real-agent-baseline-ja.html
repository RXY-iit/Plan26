Sim2Real Agent / Navigation
Baseline 検証報告

Simulation で組み上げた Agent / Skill 層を実機（real lab）に移植し、実際のロボットで動作させる検証を実施。
本日、狭い通路を含む go to sofa タスクの完全な機能フローが実機で成功。一方で、実運用に向けた信頼性面の課題も明確になった。

📅 2026-07-18 🤖 robot_ws（real lab） 🗺 l402_2d_map_clean_0509 📡 ROS_DOMAIN_ID=13

今回の要点

  • Simulation で構築した Agent / Skill / Dashboard、semantic map、Nav2、狭路（narrow passage）ロジックを実機へ移植
  • go to sofa の狭路タスクが実機で完全成功（意味解析 → 窄路整列 → 走行 → 到達判定 → Agent DONE）
  • Joy-Con 応答性、AUTO 制御信号の連続性、Localization Recovery、カメラ・モーター監視を改善
  • 機能面の baseline は通過。一方で Modbus 通信タイムアウトなど、実機特有の信頼性課題が残存
  • 実機でのタスク実行の様子とスクリーン録画・実カメラ映像をあわせて記録
🎯 結論 — 機能 Baseline は通過、信頼性 Baseline は未達
機能面 go to sofa の完全フローが実機で成功

本日、実機の local costmap を修正した後、go to sofa が2回目の完全成功を記録。窄い通路入口に到達しただけでなく、以下をすべて実行できたことをログで確認した。

自然言語命令→ semantic target 解析→ カメラ navigation 姿勢復帰→ AUTO / localization gate→ global plan・候補 approach 確認
窄路入口整列→ narrow profile 適用→ 窄路 waypoint→ sofa final goal→ Agent DONE

これにより、Agent/Skill スケジューリング・semantic map・Nav2・実機 localization・窄路ルール・運動モード/安全層・足回り制御・Dashboard・ログ連携が、simulation から real robot へ協調して移植できることが実証された。

信頼性面 「無人運用に耐える」段階にはまだ届いていない

成功したタスクの最中にも Modbus トランザクションのタイムアウトが継続的に発生していた。これまでにも電源の緩み、USB/RS-485 切断、非常停止によるロック、モーターの瞬断、カメラ画質の不安定さが実際に発生している。これらは理想的な simulation では自然に現れない問題であり、実機側で個別に解決・統計的に検証する必要がある。

🔌 今回 Sim2Real で行ったこと（概要）
  • Agent / Skill / Dashboard を simulation checkpoint から実機用に移植（real profile・実機地図・real-mode capability gate）
  • 実機 Semantic Map と窄路（narrow passage）の annotation を整備・校正
  • Navigation の窄路ロジック（速度制限・入口整列・中心線制約）を実機に適用
  • Joy-Con / AUTO の制御信号を安定化し、カクつきや停止遅れを改善
  • Localization Recovery のロジックを改善（initialpose 直後のズレ対策など）
  • Camera・Lift・Perception を実機フィードバックで校正・整備
  • Motor・Modbus 通信の安定化と Dashboard 監視・再起動ツールを追加
📊 本日（2026-07-18）の実行結果（概要）

本日 3 回の Agent セッションを実施。前半 2 回は窄路内で人手キャンセルとなったが、local costmap を修正した 3 回目で go to sofa が完全成功（約 64 秒、west→east のフォールバックや入口整列・waypoint・final goal を含むフルフロー）。

一方、成功したタスクの最中にも Modbus 通信のタイムアウトが多発しており、機能面の baseline は通過したものの、信頼性面の検証はこれからという位置づけ。

⚖️ Simulation と Real Robot の役割分担
Simulation で継続できること

決定的な上層のふるまいの検証と、大量の反復実験に向く：Agent parser・task plan・Skill contract・状態機、semantic target 解決・approach candidate・passage 選択、planner アルゴリズムや tolerance の初期範囲、narrow profile のルール、localization recovery のフロー、camera/lift/perception のプラン、そして実機で測定した delay・jitter・packet loss・sensor noise・blur・map offset を注入した fault-injection regression。

Real Robot でしか検証できないこと

電源線・端子・接触抵抗・負荷時電圧降下、USB-RS485/カメラの物理的な緩みや再列挙、Modbus の実応答時間とOS/DDSスケジューリング、モーター/操舵の機械的な引っかかりや滑り、footprint と実際の家具クリアランス、FAST-LIO/GICPの実環境品質、カメラの露出・ピント・振動、リフト/カメラの実可動域、そして人手 B/E-stop の実際の停止までの最悪時間。

最も効果的な Sim2Real ループは両者を別々に調整することではなく、「実機で記録 → 実測分布を抽出 → simulation に注入して再検証 → 実機で低速の受入確認」という往復。

P0電気・通信の安定化
  • モーター電源・共通GND・RS-485・USBの再固定とstrain relief追加
  • 3台のドライバ入力端での電圧測定（起動・横移動・急旋回・窄路操舵を重点的に）
  • /dev/ttyUSB0 を /dev/serial/by-id/... に固定しUSB再接続を監視
  • Modbus トランザクション単位でlatency histogram・timeoutバースト・再試行を統計化
P1運動・Localizationの実測指標化
  • /nav2/cmd_vel・/cmd_vel・/drive_vel・/drive_odom の頻度とp95/p99 gapを記録
  • 操舵誤差の分布を採取し、現行閾値（200 tick）が妥当かを判断
  • GICP score・pose age・settling・recovery結果とDashboard/RViz表示の整合性を検証
P1Camera / Perceptionの改善
  • 撮影前に底盘・雲台の静止を確認し、0.5〜1.0秒待ってから撮影
  • 露出/フォーカス固定でmotion blurと低照度長時間露光を切り分け
  • 9視点ごとの鮮明度・露光時間・検出信頼度を記録し、機体固有の閾値を作る
P2信頼性の受入基準（回帰試験）

「安定して動く」を定量的な基準として定義する：

  • go to sofa 連続20回、成功率95%以上、衝突・E-stop・motor dropoutゼロ
  • 完全なタスク実行中に250ms Modbus completion timeoutがゼロ
  • MANUAL deadman・Bキャンセル・Dashboard MANUALをそれぞれ10回試験し、即時停止かつ旧指令が残らないこと
  • 3本の窄路を双方向・異なる開始姿勢でそれぞれ検証
  • 実機計測のtimeout/jitter/noiseをsimulationのfault-injection回帰に反映
上記基準を満たすまでは、試験は必ず現場の人が立ち会い、Bボタンとハードウェア非常停止をいつでも使える状態で行う。
