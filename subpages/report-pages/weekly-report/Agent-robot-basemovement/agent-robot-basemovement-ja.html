🏛 階層型アーキテクチャ設計
Design 全体システム構成 — 三層アーキテクチャ

自然言語コマンドから実機制御まで、責務を明確に分けた三層構成を採用しています。

L3
Agent Layer src/robot_agent
ユーザーコマンドを解析し、複数 Skill を組み合わせた実行計画を作る層。Mission / Navigation / Localization / Perception Agent が含まれる。ここで LLM Routing を使用。
L2
Skill Layer src/robot_skills
ROS topic / action / sensor / semantic map を安全な再利用可能 API に変換する層。Python / rclpy で実装。LLM は使用しない。
L1
Navigation & Control Nav2 / GICP / safety layer
先週完成した自律ナビゲーションスタック。L2 Skill からのみ呼び出す。
LLM はあくまで「曖昧な言語解析の補助」として使用。実際の移動・カメラ・認識・安全確認は typed Skill 経由のみで実行する。
Flow コマンドから実行までの全体フロー
自然言語コマンド → Intent 解析
L3 Agent → Skill Plan
Mission Agent → ROS2 Skill 実行
L2 Skill Layer → Dashboard 可視化

例：「06棚に赤い箱がありますか」→ resolve target → await AUTO → goto pose → scan 9方向 → detect object → 結果報告

🔰 Skill と Agent の境界線
Concept なぜ Skill と Agent を分けるのか
レイヤー問いかけ例
Skill（L2） How — どう実行するか goto_pose：Nav2 で指定 pose へ移動し、成功/失敗を返す
Agent（L3） What / Why / When / What next 「近場」の意味は何か・失敗時に別 approach pose を試すか・Human に聞くか
従来の Waypoint 列（幾何座標の羅列）に比べ、Skill Plan は意味解釈・安全前置条件・構造化エラー処理の三層が加わる。これが Waypoint から Agent 系への進化点。
L3 Agent Layer の構成 — 「今何ができるか」をリアルタイムに実行判断する層

ユーザーコマンドを解析し、複数の Skill を組み合わせた実行計画を作り、健康状態や結果に応じて回復・継続・人間確認を判断する層。real lab でのテストを重ね、Recovery や Dashboard の監視項目を拡充しました。

🧠 Intent Routing — 三層設計思想
Design Deterministic → Embedding → LLM Fallback

ロボット制御での LLM 単独使用は遅延・コスト・安全性の問題がある。そのため多段階ルーティングを採用：

Deterministic
<1 ms · ルール/正規表現 → Embedding
5〜20 ms · 意味検索 → LLM Fallback
300 ms+ · 複雑コマンド
層処理時間得意分野コマンド例
Deterministic
if-else / キーワード		<1 ms緊急停止・安全コマンド（これだけは LLM に任せない）止まれ、停止
Embedding
multilingual-e5-small		5〜20 ms同義語・自然言語バリエーションのコマンド少し待ってください、止まって、待って
LLM Fallback
qwen2.5-3b · ローカル		300 ms+複雑・多段階・曖昧な指示今日はここまでにして、残りは午後に続けよう。
このパターンは特定の論文ではなく、2023〜2026 年に AI Agent / ロボットシステムで自然に収束してきたエンジニアリングベストプラクティス。Claude Code の Skill Routing、MCP Tool 選択、企業 FAQ システムなどで広く採用されている。
Policy LLM が呼ばれるタイミングの制約

LLM は毎回呼ばれず、あくまで MissionIntent JSON への変換のみを担当します。

  • ROS topic 名や座標を LLM に生成させない
  • motion / safety / contact を直接 LLM に許可しない
  • 安全系コマンドは必ず Deterministic で処理する

💡 Agent & Skill パターンの価値
Value 従来の Waypoint ナビゲーションとの比較

従来の Waypoint 方式（座標列を直接渡す）に対し、Agent & Skill パターンは以下の価値を持ちます：

  • LLM との親和性：大規模言語モデルが解析・指示しやすい抽象化レベル
  • 人間が監視・理解しやすい：Dashboard でロボットの思考過程・行動履歴を可視化
  • ネットワーク構造：一長串のコードを「任意に組み合わせ可能なネット状構造」に解剖。各分岐が独立して拡張できる
  • 上層 Agent 構築への基礎：将来の上位 Agent システムから機械的に監視・呼び出すことも可能な設計
Waypoint が「直接 SQL（Structured Query Language） を書く」なら、Skill Plan は「ORM（Object-Relational Mapping）」に相当。底層は同じことをしているが、上層に意味・検証・エラー処理が加わる。
Policy 採用した設計方針
Local-first Skill-first LLM fallback only Semantic map 駆動 停止後 Perception AUTO 時・曖昧時は Human 確認 Localization 回復を Navigation より優先

採用しなかった方針：

LLM が直接 ROS topic を publish LLM が座標を生成 固定 Waypoint として座標を覚える 検出を完全に Cloud VLM に任せる
